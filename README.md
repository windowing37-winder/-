# ccshu-reading

> 自用社科／哲学总结模式。不是"让模型总结一本书"，而是一套**有固定产物、固定篇幅、固定纪律**的读书流程。

一个给智能体（Codex / Claude Code 等）用的**深度阅读技能**。把「读一本书」拆成三层产出：

```
笔记（深度理解，慢）  →  概念卡（快速调用，小）  →  交火页（思想生产，新判断）
```

---

## 它解决什么

| | 常见做法 | 本技能 |
|---|---|---|
| 产物 | 一份平铺的内容提要 | 三种分工明确的产出：笔记 / 概念卡 / 交火页 |
| 篇幅 | 随模型心情，常常很薄 | **写死**：万字精读 1–2 万字；逐章精读每章 5000–6000 字 |
| 引语 | 模型"记得"什么就写什么 | **只引库内实有的**；库内没有就明写"需回原文核"，不许凭印象补写 |
| 推断 | 和作者原意混在一起 | **四档分离**：作者原意 / 原文事实 / 合理推断 / 无法确认 |
| 争论 | 「A 认为…B 认为…」（并列罗列） | **多立场坐标系**：标出各家在哪条轴上分歧、依赖什么前提、哪些分歧不可判定 |

## 四模式

### 书籍

| 模式 | 名称 | 篇幅 | 什么时候用 |
|---|---|---|---|
| **A** | 单文件笔记 | 1–2 千字 | 轻读、已读完的回顾、不逐章 |
| **B** | 外文科精读 | 1–2 万字（体例同 C） | 外文书：通读原文后直接产出中文精读，不留翻译稿 |
| **C** | 万字精读 | 1–2 万字 | 快速掌握核心：跨章重组 3–6 个论题 |
| **D** | 逐章精读 | 每章 5000–6000 字 | 最重要的书、10–30 万字原文；每章做整体总结 |
| **E** | 分段精读 | 每段 6000–8000 字 | 不按章节：章节太碎或太长，或思想脉络比章节结构更重要 |

**C 与 D 是二选一**：C 是 D 的缩略版（论题视角），D 是 C 的逐章展开（顺序视角）。

**D 的写法**：每章一篇，从头到尾有逻辑性和整体性；不作逐段解读，引用原文用斜体嵌在行文里。
**D 的流程**：先纵览全书 → 先写第一章交用户校准 → 确认后一口气完成其余 → 最后写总结回应。

### 论文

A 单篇笔记／B 文献综述（多篇同议题）／C 深度解读／D 逐节精读。
按原文体量分档：<10 页 → 轻量档；10–20 页 → 中档；**>20 页 → 6000 字起**。

## 方法论来源

这套读书法不是凭空来的，来源四条：

- **艾德勒《如何阅读一本书》**——分析阅读与主题阅读的规则（四层次：基础 / 检视 / 分析 / 主题）
- **卢曼卡片盒笔记法（Zettelkasten）**——概念卡与"带理由链接"
- **社科／哲学论证阅读的批判纪律**——战场定位、概念三问、论证追踪、防上当清单、批评四标准
- **库内长期实践积累的补充**——表述纪律四档、交火页多立场体例

## 立场纪律：用谁的观点

次序不可颠倒：

| 次序 | 观点是谁的 | 要求 |
|:--:|---|---|
| 1 | **作者的** | 原意优先；与原文事实、你的推断四档分离 |
| 2 | **多立场的** | 并置、对照、交锋；标出各自依赖的前提 |
| 3 | **你自己的** | 明写"据此可推断"或"个人判断"，不得混入前两者 |

社科与人文的争论**答案随立场变化**，所以总结**不替读者选边**：复述优先于批评，立场必须外显，**不可判定就明说不可判定**。

## 三条硬纪律

1. **引语只引实有的**——原文引语只能取自已有笔记或概念卡。不得凭记忆或印象补写。库内缺此语时明写"需回原文核"，其余改为间接转述。
2. **表述纪律四档**——作者原意（需原文＋出处）／原文事实与数据（保留完整数值、单位、时间范围、样本）／合理推断（写明"据此可推断"）／无法确认（明写"待考"）。**禁止把推断写成作者的意思。**
3. **先推荐、后动手**——凡涉及"选哪个档位""抽哪些概念""写哪几个交锋点"，先给推荐与理由，**等用户拍板**再落笔。不要问"你要哪个模式"，要给判断。

## 交火页：多立场对比，不是两方对打

社科与人文的争论**答案随立场变化**。所以交火页的目标不是"决出胜负"，而是**把更多立场摆进一个坐标系，让它们碰撞，并标出各自依赖的前提**。

推荐结构：

1. **问题界定**——这个争论到底在争哪一句可判真假的话
2. **分歧轴**——2–3 条关键分歧轴（如：秩序是奠基还是拒绝 × 分析单位是国家还是社会 × 判准是有效性还是正义），把各家标注到轴上
3. **各家立场**——主张 → 关键论据（带引语编号）→ **它依赖但往往不言明的前提** → 它对其他各方的回应 → 它自己的软肋
4. **交叉攻击矩阵**——一张表，行＝立场，列＝被攻击点，让碰撞成网络而两两对打
5. **判准与不可判定**——哪些分歧原则上可解，哪些是**前提之争、在体系内不可判定**。要明说"此处不可判定"，不许强行裁决
6. **未解决的问题 + 缺的对话者**

**禁止和稀泥**：若写完之后各方立场读起来彼此兼容、都"很有道理"，那一定失败了。

## 安装

把本目录放到智能体的技能目录下。Codex 为 `$CODEX_HOME/skills/`。

Windows 上若想让实体文件待在别处（例如单独一个 `D:\skills\` 管理所有技能），用目录连接：

```cmd
mklink /J "%USERPROFILE%\.codex\skills\ccshu-reading" "D:\skills\ccshu-reading"
```

## 结构

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 流程与决策：四模式速查、六个动作入口、高频纪律、交火页体例 |
| `references/four-modes.md` | 四模式的精简默认版（**仅在目标库没有自己的模板时使用**） |
| `references/disciplines.md` | 表述纪律、批评四标准、概念三问、防上当清单 |

## 一个设计取舍：流程内联，体例指路

`SKILL.md` 把"什么时候做什么、按什么顺序、哪些坑不能踩"全部写死；而具体体例（模板、篇幅细节）**优先指向目标知识库自己的 `_templates/`**，只在本技能 `references/` 里放一份精简默认版。

好处：知识库改模板时，技能不需要跟着改，**不会出现两份互相漂移的规则**。

优先级：目标库的 `AGENTS.md` > 目标库的 `_templates/` > 本技能 `SKILL.md` > 本技能 `references/`。
